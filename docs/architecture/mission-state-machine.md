# 陆空协同无人机系统统一状态机

版本：V1.0
适用题目：D题《陆空协同无人机系统》
配套机器可读规范：`mission-state-machine.yaml`

## 1. 设计目标

本方案统一规定飞机、小车和电脑地面站在任务各阶段的职责、状态转换、通信消息和异常处理。

核心原则：

- 小车是任务启动源；按键消抖后锁存请求并保持电机关闭10秒供人员撤离，
  倒计时结束后才发送 `TASK_START` 并启动。
- 起步不要求摄像头看到A点圆点或横线；10秒倒计时结束后以40 mm/s直行搜索
  普通线，识别成功后进入正常巡线，3 s仍失败则停车进入故障。
- 飞机主控是全局任务状态的唯一权威；通信采用三条点对点链路，不设置路由主节点。
- 地面站只负责显示、记录、查询和紧急中止，不参与正常任务决策。
- `FOLLOW` 同时负责伴飞和等待C点，不设置 `ACTION_WAIT_C`。
- 小车越过C点后自主减速，飞机自动进入 `DROP` 或 `LAND_CAR`。
- 飞机完成动作后通知小车恢复速度；通信异常时，小车越过D点后自主恢复。
- 所有具有副作用的消息必须携带 `run_id`，重复消息不得重复触发动作。

## 2. 系统角色

| 设备 | 主要职责 |
|---|---|
| 飞机主控 | 全局任务状态机、两条独立蓝牙链路、飞控指令、跟踪、抛投、动态起降、返航 |
| 天空端K230 | 识别小车与平台，输出相对位置、航向和置信度 |
| 小车主控 | 一键启动、循线、速度闭环、里程计、C/D/A点判断、任务减速和停车 |
| 小车K230 | 黑线检测、横向误差、航向误差、曲率和A/B/C/D大黑圆点检测 |
| PyQt地面站 | 场地和轨迹显示、状态显示、日志、链路诊断和紧急中止 |

## 3. 赛道坐标与速度参数

小车从A点出发，顺时针行驶：

| 位置 | 从A点开始的理论累计里程 |
|---|---:|
| B点 | 1500 mm |
| C点 | 3856 mm |
| D点 | 5356 mm |
| 一圈回到A点 | 7712 mm |

C到D为1500 mm长的动作区。上述数值是根据赛题图计算的初值，最终必须用实车编码器和场地标定值替换。

与AI规范一致的里程参数：

```yaml
odometry_calibration: 1.05187
point_b_path_mm: 1500
point_c_path_mm: 3856
point_d_path_mm: 5356
lap_path_mm: 7712
```

速度初值：

| 参数 | 初值 | 用途 |
|---|---:|---|
| `normal_speed_mm_s` | 150 mm/s | 正常循线并保证15秒内到达B点 |
| `action_speed_mm_s` | 80 mm/s | C—D动作区抛投或动态起降 |
| `reacquire_speed_mm_s` | 40 mm/s | 丢线恢复 |

速度切换必须使用斜坡，动作区内允许减速但不允许停车。

## 4. 状态编号

### 4.1 全局任务状态

| 编号 | 状态 | 含义 |
|---:|---|---|
| 0 | `IDLE` | 待机和自检 |
| 1 | `TAKEOFF` | 从H点起飞至巡航高度 |
| 2 | `HOVER_3S` | 抛投模式稳定悬停3秒 |
| 3 | `SEARCH` | 搜索小车和平台 |
| 4 | `FOLLOW` | 跟随小车并等待C点 |
| 5 | `DROP` | C—D区间持续伴飞并抛投 |
| 6 | `LAND_CAR` | C—D区间降落到移动平台 |
| 7 | `WAIT_5S` | 在移动平台稳定停留5秒 |
| 8 | `RETAKEOFF` | 从移动平台再次起飞 |
| 9 | `RETURN` | 返回H点 |
| 10 | `LAND_H` | 降落到H点 |
| 11 | `DONE` | 飞机任务完成 |
| 12 | `ABORT` | 人工紧急中止 |
| 13 | `FAULT` | 不可恢复故障 |

### 4.2 小车本地状态

| 编号 | 状态 | 含义 |
|---:|---|---|
| 0 | `READY` | 自检完成，等待启动按键 |
| 1 | `STARTING` | 去抖、清零里程、锁存任务参数 |
| 2 | `NORMAL_TRACK` | 正常速度循线 |
| 3 | `ACTION_SLOW` | C—D动作区低速循线 |
| 4 | `LOST_HOLD` | 短时丢线，保持最后转向 |
| 5 | `REACQUIRE` | 低速重新寻找黑线 |
| 6 | `FINISH_CONFIRM` | 回到A点后的终点确认 |
| 7 | `DONE` | 一圈完成并停车 |
| 8 | `ABORT` | 人工中止并立即停车 |
| 9 | `FAULT` | 不可恢复故障并停车 |

### 4.3 赛道事件

| 编号 | 事件 | 含义 |
|---:|---|---|
| 1 | `B_CROSS` | 越过B点 |
| 2 | `C_ENTER` | 越过C点并进入动作区 |
| 3 | `D_EXIT` | 越过D点并离开动作区 |
| 4 | `A_FINISH` | 完成一圈并重新识别A点大黑圆点 |

当前高强度底板机械参数：轮径约47 mm、两轮中心轮距432 mm；左右电机交换后，当前左轮（原右电机）为41589 count/rev，当前右轮（原左电机）为41348 count/rev。

## 5. 全局任务流程

### 5.1 抛投模式

```text
IDLE
  → TAKEOFF
  → HOVER_3S
  → SEARCH
  → FOLLOW
  → DROP
  → RETURN
  → LAND_H
  → DONE
```

转换条件：

- `IDLE → TAKEOFF`：飞机收到新的合法 `TASK_START`，且飞控允许起飞。
- `TAKEOFF → HOVER_3S`：高度进入 `150±10 cm` 并稳定。
- `HOVER_3S → SEARCH`：连续稳定悬停满3秒。
- `SEARCH → FOLLOW`：天空视觉连续稳定识别小车。
- `SEARCH/FOLLOW → DROP`：收到当前 `run_id` 的 `C_ENTER`。
- `DROP → RETURN`：物资释放完成，或者收到 `D_EXIT`/动作超时。
- `RETURN → LAND_H`：飞机到达H点上方并稳定识别降落标志。
- `LAND_H → DONE`：确认着陆、停桨和飞控安全。

`DROP` 是**持续伴飞抛投**状态，不是悬停等待状态。小车在C—D区间保持动作慢速且
不停车；飞机必须持续使用视觉相对误差和小车 `CAR_POSE/CAR_STATE` 匹配前向速度、
横向位置和航向。满足连续稳定的相对位置与置信度门限后，飞机在仍伴飞的情况下单次
释放物资；释放前后都不能把速度目标清零或改为定点悬停。

### 5.2 动态起降模式

```text
IDLE
  → TAKEOFF
  → SEARCH
  → FOLLOW
  → LAND_CAR
  → WAIT_5S
  → RETAKEOFF
  → RETURN
  → LAND_H
  → DONE
```

转换条件：

- `IDLE → TAKEOFF`：飞机收到新的合法 `TASK_START`。
- `TAKEOFF → SEARCH`：高度进入 `150±10 cm` 并稳定，不执行3秒悬停。
- `SEARCH → FOLLOW`：天空视觉稳定识别小车。
- `SEARCH/FOLLOW → LAND_CAR`：收到当前 `run_id` 的 `C_ENTER`。
- `LAND_CAR → WAIT_5S`：飞机稳定落在移动平台上。
- `WAIT_5S → RETAKEOFF`：连续稳定停留满5秒。
- `RETAKEOFF → RETURN`：重新起飞并恢复到 `150±10 cm`。
- `RETURN → LAND_H`：到达H点上方并完成对准。
- `LAND_H → DONE`：确认着陆和停桨。

### 5.3 C点仍未找到小车

若小车越过C点时飞机仍处于 `SEARCH`，飞机仍进入 `DROP` 或 `LAND_CAR`。动作状态的前半段继续完成搜索、锁定和对准，但只有满足视觉稳定条件后才能释放物资或开始下降。

若小车越过D点仍未完成动作：

- 禁止继续抛投或尝试接触平台；
- 记录 `ACTION_DEADLINE_MISSED`；
- 飞机进入 `RETURN`；
- 小车恢复正常速度；
- 地面站保留任务失败原因，但继续显示返航过程。

## 6. 三端职责矩阵

| 全局状态 | 飞机 | 小车 | PyQt地面站 |
|---|---|---|---|
| `IDLE` | 自检飞控、视觉、蓝牙和执行机构 | 电机关闭，检查K230、编码器和按键 | 显示设备在线、自检和任务模式 |
| `TAKEOFF` | 接收新 `run_id`，起飞至150 cm | 清零里程，以正常速度启动循线 | 开始计时和日志 |
| `HOVER_3S` | 抛投模式稳定悬停3秒 | 正常速度循线 | 显示悬停倒计时 |
| `SEARCH` | 搜索并接近小车 | 正常速度循线并发送位置 | 显示双方位置和搜索状态 |
| `FOLLOW` | 匹配小车位置、速度和航向，同时等待C点 | 正常速度循线并计算距C/D点距离 | 显示跟随误差、置信度和剩余路程 |
| `DROP` | 持续匹配小车速度、位置和航向；满足门限时单次释放物资 | 保持动作慢速且不停 | 显示伴飞误差、抛投阶段和结果 |
| `LAND_CAR` | 在C—D区间跟随下降至移动平台 | 保持动作慢速 | 显示下降高度和平台误差 |
| `WAIT_5S` | 在平台稳定停留至少5秒 | 保持动作慢速 | 显示停留倒计时 |
| `RETAKEOFF` | 从移动平台起飞并恢复巡航高度 | 保持动作慢速 | 显示平台再起飞 |
| `RETURN` | 返回H点并搜索标志 | 恢复正常速度 | 显示返航轨迹 |
| `LAND_H` | 对准H点并平稳下降 | 正常循线并准备A点终点确认 | 显示H点降落状态 |
| `DONE` | 停桨并保持遥测 | 完成一圈后在A点停车 | 保存最终结果 |
| `ABORT` | 停止新动作并执行安全降落 | 立即关闭电机驱动 | 红色显示人工中止 |
| `FAULT` | 返航、就近降落或交由飞控失效保护 | 停车并上报故障 | 显示故障源和最后有效状态 |

## 7. 小车本地状态机

正常流程：

```text
READY
  → STARTING
  → NORMAL_TRACK
  → ACTION_SLOW       C_ENTER
  → NORMAL_TRACK      飞机进入RETURN，或D_EXIT/慢速超时
  → FINISH_CONFIRM
  → DONE
```

丢线恢复：

```text
NORMAL_TRACK/ACTION_SLOW
  → LOST_HOLD
  → REACQUIRE
  → 返回丢线前状态

REACQUIRE最终超时 → FAULT
```

具体规则：

1. `READY` 状态下即使收到有效视觉帧也不能自动行驶；按键锁存后仍保持READY
   和电机关闭，完成10秒安全倒计时后才进入STARTING。
2. `STARTING` 完成 `run_id`递增、任务模式锁存、里程和圈数清零。
3. 到达C点时，小车立即进入 `ACTION_SLOW`，不等待飞机或地面站确认。
4. `C_ENTER` 按固定周期重复发送，直到离开动作区。
5. 抛投模式收到飞机 `TASK_STATE=RETURN` 后恢复正常速度。
6. 动态模式在飞机完成再起飞并进入 `RETURN` 后恢复正常速度。
7. 若飞机链路失效，小车在 `D_EXIT` 或动作慢速超时后自主恢复正常速度。
8. 起步时看不到A点圆点和横线不影响启动；完成10秒安全倒计时并真正开始任务时，
   小车清零累计里程 `path_mm`。
9. 小车以地图累计里程作为B/C/D/A事件主判据：1500 mm触发B，3856 mm触发C
   并进入动作慢速，5356 mm触发D并恢复正常速度，7712 mm触发A停车。
10. K230大黑点检测保留为画面诊断和后续标定信息，不参与任务点计数；任何圆点
    漏检、重复检测或误检都不得改变任务状态、车速或停车位置。

## 8. 蓝牙拓扑

三个设备各使用两块ECB02，组成三条独立点对点链路：

```text
飞机主控 ECB02-A ───── ECB02-A 小车主控（USART2）
飞机主控 ECB02-B ───── ECB02-A 地面站（USB-UART）
小车主控 ECB02-B（USART1）───── ECB02-B 地面站（USB-UART）
```

飞机负责：

- 接收小车的启动、位置、状态和赛道事件；
- 向小车周期发送权威 `TASK_STATE`；
- 通过独立链路向电脑发送飞机状态、位置和动作状态；
- 接收地面站直发的 `TASK_ABORT`。

小车将遥测和赛道事件分别直发飞机与地面站。地面站把 `TASK_ABORT` 分别直发飞机和小车。任何地面站链路掉线都不影响飞机—小车链路。

不使用ECB02一主多从能力。飞机、小车、地面站均固定使用两块ECB02和两路串口，上层LXS1协议使用三条点对点链路。

参考：[ECB02C官方手册](https://eciot.cn/download/ecb02/ECB02C-Datasheet-V1.0.pdf)。

## 9. 通信消息

### 9.1 TASK_START（0x10）

发送方：小车；接收方：飞机。

```text
run_id:u8
task_mode:u8              1抛投，2动态起降
normal_speed_mm_s:u16
action_speed_mm_s:u16
```

### 9.2 TASK_STATE（0x12）

发送方：飞机；接收方：小车、地面站。

```text
run_id:u8
task_mode:u8
global_state:u8
result:u8                 0进行中，1成功，2失败，3中止
fault_code:u16
elapsed_ms:u32
car_path_mm:u32
```

### 9.3 CAR_STATE（0x31）

发送方：小车；接收方：飞机和地面站，两条点对点链路分别直发。

```text
run_id:u8
car_state:u8
speed_mode:u8             0停车，1正常，2动作慢速，3恢复
line_valid:u8
speed_mm_s:u16
fault_code:u16
path_mm:u32
lap:u8
```

`lap=1`在 `path_mm >= 7712` 时置位，并立即触发 `A_FINISH`。

### 9.4 CAR_POSE（0x32）

发送方：小车；接收方：飞机和地面站，两条点对点链路分别直发。

```text
run_id:u8
x_mm:i16
y_mm:i16
heading_deg:i16
path_mm:u32
```

### 9.5 TRACK_EVENT（0x33）

发送方：小车；接收方：飞机和地面站，两条点对点链路分别直发。

```text
run_id:u8
event:u8
path_mm:u32
```

`C_ENTER` 在C—D动作区内周期发送，不能只依赖一个事件帧。

### 9.6 动作和故障消息

- `DROP_STATE（0x50）`：抛投未开始、对准、释放、成功或失败。
- `LAND_STATE（0x51）`：下降、着陆、停留、再起飞、成功或失败。
- `FAULT（0x60）`：故障来源、故障码和严重级别。

现有LXS1文档中 `TASK_STATE`、`CAR_STATE` 的字段下标存在重叠，实现前必须按本节重新整理C、Python和PyQt三端结构。

## 10. PyQt地面站

软件结构：

```text
PyQt主线程
├─ 场地图和轨迹绘制
├─ 状态、告警和任务结果
└─ 查询与紧急中止

串口工作线程
├─ pyserial或QSerialPort收发
├─ LXS1增量解析
├─ 在线超时和丢帧统计
└─ CSV/JSON日志队列
```

界面至少显示：

- 400 cm × 500 cm场地图以及A/B/C/D/H点；
- C—D动作区；
- 飞机和小车的实时位置、航向和历史轨迹；
- 全局任务状态、小车本地状态和速度模式；
- 距C点、D点的路程和预计剩余时间；
- 飞机高度、速度、视觉置信度和跟随误差；
- 抛投、着陆、停留5秒和再起飞结果；
- 两条蓝牙链路的在线状态、最后收包时间和丢帧统计。

正式任务中地面站不提供手动驾驶，只允许查询和紧急中止。电脑程序退出或地面站链路断开不能影响飞机和小车继续执行任务。

## 11. 超时与故障策略

| 情况 | 处理 |
|---|---|
| 小车视觉短时丢失 | `LOST_HOLD`，降低速度并沿用最后转向 |
| 小车视觉继续丢失 | `REACQUIRE`，以恢复速度搜索黑线 |
| 小车视觉最终超时 | `FAULT` 并停车 |
| 飞机视觉短时丢失 | 保持高度和最近匹配速度，继续搜索 |
| 飞控状态超时 | 停止发送新的运动动作，进入安全策略 |
| 地面站离线 | 只标记离线，飞机和小车继续任务 |
| 飞机—小车链路在动作区失效 | 小车到D点或慢速超时后恢复正常速度 |
| 动作未在D点前完成 | 取消动作、记录失败、飞机返航 |
| 收到 `TASK_ABORT` | 飞机安全降落，小车立即停车 |

## 12. 系统不变量

1. 飞机是全局任务状态的唯一权威，但不是通信路由节点。
2. 地面站离线不能中断正常任务。
3. 小车到达C点自主减速，不依赖无线确认。
4. 抛投完成或平台再起飞完成后，小车恢复正常速度。
5. 小车越过D点或动作慢速超时后强制恢复正常速度。
6. 小车在C—D动作区只减速、不停车。
7. 所有副作用消息必须按 `run_id` 幂等。
8. 重复 `C_ENTER` 不得重复触发抛投或降落。
9. `TASK_STATE` 和 `C_ENTER` 必须周期发送，不能依赖单帧。
10. 飞机释放物资、开始下降、解锁起飞等动作必须由状态入口或显式子阶段单次触发。
11. `DROP`期间飞机持续伴飞小车；释放物资不是悬停或停车条件。

## 13. 验收标准

- 顺时针A→B→C→D→A的里程映射正确。
- 小车启动后15秒内越过B点。
- 小车越过C点后平滑进入动作慢速。
- 飞机从 `SEARCH` 或 `FOLLOW` 自动进入 `DROP/LAND_CAR`。
- 抛投期间小车连续行驶，飞机持续匹配其速度、位置和航向；释放前后均不悬停等待。
- 抛投完成后小车恢复正常速度。
- 动态任务在降落、停留5秒和再起飞期间保持动作慢速。
