# 小车 K230 黑线视觉

本目录是亚博 K230 视觉模块的小车巡线程序。默认使用 QVGA 灰度图、多条水平
ROI、低频 Otsu 自适应阈值和位置跟踪，在不启用屏幕显示及逐帧日志时，以
40 Hz 向小车 STM32F407 发送识别结果。程序会请求 640×480@60 fps 的相机输入
模式，再由 ISP 输出 320×240；旧固件不支持带参数的 `Sensor` 构造函数时会自动
退回默认模式。

## 文件

- `main.py`：相机、UART 和主循环。
- `vision_config.py`：安装、识别、滤波、标定及串口参数。
- `line_vision.py`：黑线识别与几何量计算。
- `lxs1_uart.py`：LXS1 `VISION_LINE` 帧发送。
- `tests/test_lxs1_uart.py`：可在电脑上运行的协议字节测试。

## 调试画面

程序默认初始化亚博配套 `Display.ST7701` 屏，分辨率为 640×480。视觉识别保持
320×240。相机通道0以 YUV420SP 640×480 直接绑定到 ST7701 的 `VIDEO1` 层，
由 K230 显示硬件连续输出；相机通道1单独输出 320×240 灰度图供算法处理。
调试标记绘制在两张交替使用的透明 ARGB8888 OSD 缓冲区上。这种视频层与算法层
分离的方式不再由 Python 缩放整张画面，可避免全屏撕裂并降低 CPU 占用。叠加内容：

- 灰色矩形：5 条识别 ROI；
- 灰色竖线：标定的相机光轴中心；
- 白色十字和连线：本帧识别到的黑线中心；
- `OK/LOST`、置信度 `C`、阈值 `T`、有效采样数 `N`、圆点采样数 `M`；
- 横向误差 `LAT`、航向误差 `H`、曲率 `K`、识别帧率和串口错误数。

显示默认约 15 Hz 刷新，识别和串口仍按各自最高帧率及 40 Hz 节拍运行。当前配置：

```python
DISPLAY_TYPE = "ST7701"
DISPLAY_WIDTH = 640
DISPLAY_HEIGHT = 480
DISPLAY_TO_IDE = False
```

亚博配套屏必须使用 640×480；此前的 320×240 不属于 ST7701 支持的面板时序，
会导致屏幕无法初始化。若更换其他尺寸 ST7701，必须按对应屏幕规格修改宽高。
需要同时在实体屏和 IDE 查看时，将
`DISPLAY_TO_IDE=True`，但这会增加内存及处理开销。正式高速运行可把
`DISPLAY_ENABLED=False`。

如果上电后屏幕完全不亮，先单独运行 `display_test.py`。该程序不初始化相机和
UART，只显示彩条和文字：

- 测试程序能显示：屏幕硬件正常，检查 `main.py` 的终端错误信息；
- 测试程序报不支持 ST7701：需要更新或更换匹配开发板的 CanMV 固件；
- 使用的不是亚博配套屏：按屏幕真实分辨率修改宽高后重试；
- 测试程序也完全无背光：检查屏幕排线方向、插座锁扣、供电和背光电路。

## 接线

默认按亚博 K230 12 针接口的 UART3 配置：

| K230 | STM32F407 | 作用 |
|---|---|---|
| GPIO32 / UART3_TXD | PB11 / USART3_RX | K230 发送视觉结果 |
| GPIO33 / UART3_RXD | PB10 / USART3_TX | 预留 STM32 下发参数 |
| GND | GND | 必须共地 |

串口为 `115200, 8-N-1`。TX 与 RX 必须交叉连接。K230 的 UART IO 电平需要按
实际模块和固件确认，不能接入 5 V TTL；若该组 IO 是 1.8 V 域，必须增加电平
转换。亚博排针资料中部分 5 V 脚标为输出，若要从底板向模块供电，应先确认该
版本硬件是否允许反向输入，不能只依据排针名称直接供电。

亚博定制固件通常可使用 GPIO32/33 的 UART3。若使用通用 CanMV 固件且 UART3
被系统终端占用，请在 `vision_config.py` 中改用空闲的 UART1、UART2 或 UART4，
同时修改对应 TX/RX 管脚；程序会根据 `UART_CHANNEL` 自动选择 FPIOA 功能。

## LXS1 输出

每帧固定19字节：

```text
AA 55 | 0E | 05 | 04 | 42 | DATA(11 bytes) | 0D 0A
```

`DATA` 按小端序排列：

| 偏移 | 类型 | 内容 |
|---:|---|---|
| 0 | `u8` | `valid`，1 为有效 |
| 1 | `u8` | `lost_count`，连续丢线帧数 |
| 2 | `u16` | `confidence`，0～1000 |
| 4 | `i16` | `lateral_error_mm` |
| 6 | `i16` | `heading_error_deg` |
| 8 | `i16` | `curvature`，单位为 0.001/m |
| 10 | `u8` | `marker_detected`，已锁定轨迹附近检测到大黑圆点时为1 |

无校验位、无 CRC、无保留字节。丢线时立即发送
`valid=0, confidence=0, lateral=0, heading=0, curvature=0`，不会继续发送上一次
有效控制量。

`marker_detected`保留用于赛道大黑点诊断和后续视觉标定，但不再推进小车任务。
STM32以任务开始后清零的累计里程 `path_mm` 为主判据：1500 mm触发B事件，
3856 mm进入C点动作慢速，5356 mm在D点恢复正常速度，7712 mm回到A点停车。

K230允许圆点在远端只覆盖1条水平采样带，但要求连续2帧成立，并使用8帧关闭
迟滞。圆点通道独立于巡线 `valid`，只作为调试画面和通信诊断字段使用；圆点的
漏检、重复检测或误检均不得改变B/C/D/A事件、减速区间或停车位置。
圆点宽度从70像素起判定，并独立扫描每条ROI内的全部连通域；即使巡线评分选择了
同一ROI里的窄线段，也不会漏掉同时存在的宽圆点候选。

图像先使用Otsu自适应阈值显式二值化，再执行一次轻量形态学去噪；若CanMV固件
不支持对应API，会自动退回原来的直接阈值识别流程。

符号约定：

- 黑线位于图像中心右侧时，横向误差为正；
- 黑线向车辆前方延伸时偏向右侧，航向误差为正；
- 右弯曲率为正。

## 部署

1. 将本目录的四个 `.py` 程序文件复制到 K230 的同一目录。
2. 先在 CanMV IDE 中运行 `main.py`，确认没有 UART 或相机初始化异常。
3. 需要脱机启动时，将 `main.py` 及其依赖保存到模块启动脚本目录；具体位置按
   当前亚博固件说明操作。
4. 默认可直接观察 IDE 虚拟屏幕；也可临时将 `DEBUG_PRINT=True`，终端每秒输出
   一次帧率和识别状态。

## 必做标定

摄像头固定牢固后再标定，标定过程中不要改变安装高度和俯角。

1. **方向**：车头朝前放在线上。图像倒置或镜像时调整
   `CAMERA_HMIRROR`、`CAMERA_VFLIP`。
2. **光轴中心**：让车体中心对准直线，调整 `OPTICAL_CENTER_X`，使
   `lateral_error_mm` 接近 0。
3. **横向比例**：保持相机姿态不动，将车横移已知距离：
   `LATERAL_MM_PER_PIXEL = 实际横移毫米 / 识别横移像素`。
4. **前向比例**：用标定板测量采样区域的前向距离近似值，修正
   `FORWARD_MM_PER_PIXEL`。若只把曲率作为前馈量，也可通过实车转弯效果整定。
5. **曝光**：默认自动曝光。确认赛场光照后，可将 `MANUAL_EXPOSURE_US` 设置为
   实测合适值。支持新接口的固件会关闭自动曝光并锁定曝光；不支持时会安全跳过。
6. **阈值**：默认自适应。若场地光照稳定但背景干扰严重，可关闭
   `ADAPTIVE_THRESHOLD`，观察调试输出后设置 `FIXED_THRESHOLD`。
7. **ROI**：保证五条 `STRIP_CENTER_Y` 都落在赛道区域。近端不要看到车体，远端
   不要包含地平线或无关标志。

## A/B/C/D大黑圆点处理

A、B、C、D处的大黑圆点进入水平ROI时，会比普通巡线宽得多。程序不会再把它
直接判成丢线，而是在已经稳定跟踪且圆点中心靠近上一帧赛道位置时，把宽连通域
继续当作可行驶轨迹。离开圆点后仍保留进入前的普通线宽预测，因此不会在圆点
出口突然扩大搜索范围或停车。

相关参数位于 `vision_config.py`：

- `MAX_LINE_WIDTH`：普通黑线最大宽度；
- `MAX_MARKER_WIDTH`：大黑圆点形成的连通域最大宽度；
- `MARKER_MAX_CENTER_DEVIATION`：圆点中心相对历史赛道位置的最大偏差；
- `MARKER_MIN_STRIPS`：调试画面显示圆点标志所需的采样带数量。

宽黑块在尚未锁定赛道或远离历史轨迹时仍会被拒绝，避免场地边框、阴影和车体
进入画面后被误认为道路。现场应让车低速依次通过四个点，观察调试画面中 `M`
短暂大于0且状态保持 `OK`；若真实圆点仍被拒绝，先根据画面测量宽度再小幅提高
`MAX_MARKER_WIDTH`，不要直接放宽到整幅图像。

## 稳定性建议

- 不在正式程序中初始化显示屏，不逐帧 `print`。
- 相机固定曝光后通常更稳定；不同 CanMV 固件的曝光接口存在差异，建议先在
  IDE 中确定合适曝光值，再按当前固件 API 加入锁定。
- STM32 当前把超过180 ms未收到新视觉帧视为通信失效并停车；若只是收到
  `valid=0`，则以40 mm/s沿上次方向低速穿越，最多尝试3 s。
- 先低速验证符号方向，再逐步提高车速和闭环增益。
- 如果直线被大面积黑色背景吸引，缩小 `TRACK_SEARCH_HALF_WIDTH`；急弯丢线则
  适当增大该值或 `LOST_EXPAND_PIXELS`。
